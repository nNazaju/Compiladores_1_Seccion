Tema 1

¿Qué es un compilador?

Un compilador es un programa que lee un programa escrito en un lenguaje (el lenguaje fuente, normalmente de alto nivel) y lo traduce a un programa equivalente en otro lenguaje (el lenguaje destino, normalmente código de máquina o ensamblador). Al proceso completo se le llama compilación.

Un compilador nace junto con su lenguaje de programación. Su trabajo no es solo traducir: primero revisa que el código esté bien escrito y bien usado, informa los errores al programador y, si todo está correcto, produce un código destino lo más eficiente posible.

Por eso el módulo insiste en que un compilador no es un simple traductor. Un traductor convierte un texto escrito con unas normas en otro texto con normas distintas. El compilador, además, hace revisión léxica, sintáctica y semántica y entrega una escritura optimizada que la computadora puede ejecutar.

TraductorCompiladorIntérprete
Qué haceConvierte un lenguaje en otroAnaliza todo el programa y genera un programa objetoAnaliza y ejecuta las instrucciones una a una
Revisa erroresNo es su propósitoLéxicos, sintácticos y semánticos, antes de ejecutarAl llegar a cada instrucción
SalidaTexto en otro lenguajeCódigo máquina o ensamblador (archivo ejecutable)Los resultados de ejecutar el programa
OptimizaNoSí, en la fase de síntesisPoco o nada
EjemplosConvertidor de unidades de texto, transpilador simplegcc para C, rustc para RustIntérprete de Python, la consola de JavaScript
Para discutir: Java compila a bytecode y luego la JVM lo interpreta o lo compila en tiempo de ejecución (JIT). ¿Java es compilado o interpretado? La respuesta honesta es «ambas cosas, en dos etapas».
Tema 1

Lenguajes de alto y bajo nivel

Un lenguaje de alto nivel (C, Java, Python, Pascal) se acerca al modo de pensar de las personas: usa palabras como while o if, expresiones matemáticas y nombres de variables. Un lenguaje de bajo nivel (ensamblador, código de máquina) usa instrucciones que se comunican directamente con los registros y la memoria de la máquina.

El compilador es el puente entre los dos. Una sola línea de alto nivel suele convertirse en varias instrucciones de bajo nivel:

Alto nivel (C)
c = a * (b - d) / f;
Bajo nivel (ensamblador simplificado)
MOV  b, R1     ; R1 ← b
SUB  d, R1     ; R1 ← b - d
MOV  a, R2     ; R2 ← a
MUL  R1, R2    ; R2 ← a * (b - d)
DIV  f, R2     ; R2 ← R2 / f
MOV  R2, c     ; c ← R2
Ojo con una confusión frecuente: el lenguaje natural (español, inglés) es ambiguo y depende del contexto. Los lenguajes de programación se definen con reglas formales precisamente para que un programa (el compilador) pueda reconocerlos sin ambigüedad.
Tema 2

Análisis y síntesis: las seis fases

Por razones de diseño, el compilador se divide en fases. Se agrupan en dos procesos:

Análisis (parte frontal): comprueba que el programa fuente esté correctamente escrito y construye una representación intermedia de él. Síntesis (parte final): a partir de esa representación, construye el programa destino.

Análisis · fase 1

Análisis léxico

Lee el programa fuente carácter a carácter, elimina espacios y comentarios y lo fracciona en tokens: identificadores, números, operadores, signos. Registra los identificadores en la tabla de símbolos.

entra: cadena de caracteressale: secuencia de tokens
Análisis · fase 2

Análisis sintáctico

Verifica que los tokens respeten la estructura del lenguaje, definida por reglas llamadas gramáticas. Construye el árbol sintáctico. Es una de las fases más importantes.

entra: tokenssale: árbol sintáctico
Análisis · fase 3

Análisis semántico

Comprueba que cada componente se use de forma válida en su contexto: tipos compatibles, variables declaradas, conversiones necesarias (por ejemplo, de entero a real).

entra: árbol sintácticosale: árbol anotado con tipos
Síntesis · fase 4

Generación de código intermedio

Traduce el árbol a un código sencillo, independiente de la máquina, con variables temporales. El formato más usado es el código de tres direcciones: t1 = id2 + id3.

entra: árbol anotadosale: código de tres direcciones
Síntesis · fase 5

Optimización de código

Mejora el código intermedio para que se ejecute más rápido o use menos recursos: elimina temporales innecesarias, calcula constantes en tiempo de compilación. Optimizar sobre el código intermedio es mucho más fácil que sobre el fuente.

entra: código intermediosale: código intermedio mejorado
Síntesis · fase 6

Generación de código

Produce el código de máquina o ensamblador: decide qué registros usar y qué instrucciones (MOV, ADD, MUL) corresponden a cada operación.

entra: código optimizadosale: programa objeto
«El analizador léxico trabaja para el sintáctico»: el sintáctico no lee el archivo. Cada vez que necesita un componente, llama al léxico, que le entrega el siguiente token. Así el léxico funciona como una subrutina del sintáctico.
Tema 2

Dos componentes que acompañan todas las fases

Tabla de símbolos

Estructura de datos (una tabla en memoria, una lista doblemente enlazada o una tabla hash) que guarda la información de cada identificador: nombre, tipo, dirección en memoria, ámbito. Permite consultar esos datos sin volver a recorrer el programa fuente. Las operaciones básicas son insertar y buscar.

EntradaLexemaTipoDirección
id1posicionreal0
id2inicialreal4
id3velocidadreal8

Detección e informe de errores

En cada fase pueden aparecer errores. Un buen compilador informa el error con su ubicación, intenta recuperarse y continúa para detectar el mayor número posible de errores en una sola compilación. Un compilador que se detiene en el primer error es poco útil.

  • Léxico: precio # 2, el símbolo # no existe en el lenguaje.
  • Sintáctico: (base * altura / 2, falta un paréntesis.
  • Semántico: int edad = "veinte";, tipos incompatibles.
Tema 3

Ejemplos trazados del módulo

Ejemplo 1 (Pascal): suma := ultimo + penultimo. El léxico entrega 5 tokens: identificador suma, asignación :=, identificador ultimo, operador +, identificador penultimo. El sintáctico usa estas reglas:

1. <asignación> → identificador := <expresión>
2. <expresión>  → identificador
3. <expresión>  → <expresión> + <expresión>
Código intermedio
t1  = id2 + id3
id1 = t1
Optimizado
id1 = id2 + id3
Ensamblador
MOV id2, R1   ; R1 ← ultimo
ADD id3, R1   ; R1 ← R1 + penultimo
MOV R1, id1   ; suma ← R1
El módulo muestra la optimización como Id1=Temp1. Lo que el optimizador hace en realidad es eliminar la temporal: el resultado de la suma se asigna directamente a id1.

Ejemplo 2 (C): posicion = inicial + velocidad * 60. Suponemos que las tres variables son reales y que 60 es entero. Como * tiene mayor precedencia que +, la multiplicación queda más abajo en el árbol y se calcula primero.

Código intermedio
t1 = inttoreal(60)
t2 = id3 * t1
t3 = id2 + t2
id1 = t3
Optimizado
t1  = id3 * 60.0
id1 = id2 + t1
Ensamblador
MOV id3, R1    ; R1 ← velocidad
MUL #60.0, R1  ; R1 ← R1 * 60.0
MOV id2, R2    ; R2 ← inicial
ADD R1, R2     ; R2 ← R2 + R1
MOV R2, id1    ; posicion ← R2
En el módulo, el léxico describe * como «operador de suma»: es el operador de multiplicación. La conversión inttoreal(60) la agrega el análisis semántico, y el optimizador la resuelve en tiempo de compilación escribiendo directamente 60.0. Puedes reproducir este ejemplo, paso a paso, en el simulador de la pestaña Práctica.

Glosario de la sesión

Token
Componente léxico con sentido para el lenguaje: identificador, número, operador, palabra clave, signo.
Lexema
La secuencia concreta de caracteres que forma un token, por ejemplo velocidad.
Gramática
Conjunto de reglas (producciones) que definen la estructura válida del lenguaje.
Árbol sintáctico
Representación jerárquica de una instrucción según la gramática.
Código de tres direcciones
Código intermedio donde cada instrucción tiene a lo sumo un operador y tres operandos.
Registro
Pequeña memoria interna del procesador donde se hacen las operaciones (R1, R2, EAX…).
Programa objeto
Resultado final de la compilación: código máquina o ensamblador.
Intérprete
Programa que ejecuta directamente las instrucciones del fuente, sin producir un programa objeto completo.
